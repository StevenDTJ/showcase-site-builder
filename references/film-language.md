# pear.no 影片语言分析（基于实际抓取的资产）

> 计数说明：下文按**帧序列**数落 9 条（renaissance 1 + 三段桥接 v28/v51/v61 + plan/tree/flysky/trans 4 + coda 1）；若把三段桥接合起来数则是 7 组。两种数法都对，差别只在"桥接段算一段还是三段"。

以下来自对 pear.no 全部影片资产的逐帧分析：4 段 mp4（`signal`/`colossus`/`reveal`/`footer-loop`，均 1920×1080、60fps、整 10 秒）+ 7 个 WebP 帧序列（`renaissance` 362 帧、桥接段 `v28`/`v51`/`v61` 各 121 帧、`plan`/`tree`/`flysky`/`trans` 各 121 帧、`coda` 89 帧，1440/768 双分辨率）。

## 核心结论：影片里没有硬切

pear.no 的"影片"不是剪辑出来的。**每一段都是单一构图、单一连续镜头**，段落之间的转换全部靠两种方式：

1. **摄像机运动转场（ disguised as continuous takes ）**：推近一个细节 → 该细节"变成"下一场景；或拉远揭示"原来这是纸上的一张图"。
2. **首尾帧焊接**：前一段的最后一帧 = 后一段的第一帧，帧序列之间无缝相接。

### 实际的转场链（以 signal 版 hero 为例）

```text
signal.mp4（活画循环）
  └─ 滚动触发：WebGL 向 origin=[0.707,0.926] 点推近（shader 加噪点/抖动/色差）
     └─ v28 桥接序列（121帧）：镜头沿石柱推向柱顶雕像 → 柱头中空，长出树枝
        → 鸽子飞过 → 一双 hands 在树枝上嫁接（末帧 = renaissance 首帧）
        └─ renaissance 序列（362帧）：嫁接特写 → 拉远成满树梨 → 绿叶间出现
           一只金梨 → 伸手采摘 → 天鹅绒少年检视 → 切梨 → 梨分两半递给另一只手
```

`plan` 段（服务陈列区）：建筑工地围绕巨型金梨，脚手架、工人、绳索；摄影机升起旋转到正顶俯视并持续拉远——**最终揭示整个场景是纸面上一张建筑平面图**（plan 双关：平面图/计划）。

`tree` 段：白袍女子给盆栽梨树嫁接 → 金梨像气球般带彩虹光晕飘起 → 满天金梨的树。

`flysky` 段：梨树梢 → 镜头直冲云霄穿过半调网点云 → 男子在石阶上指向天空，**星光连成星座**（link-building 的隐喻：星星连线=链接）。

`coda` 段：脚手架环绕大理石碑，建筑师展读蓝图 → 镜头推入蓝图（通向申请表单）。

`trans` 段（页尾前）：星座 → 镜头下移、梨树生长 → 男女园丁浇水修剪（末帧 = footer-loop 首帧）→ 接入 10 秒循环的 footer-loop.mp4。

## 逐段主体与隐喻

影片整体是**商业模式的寓言链**，每段一个隐喻主体：

| 段落 | 主体 | 隐喻 |
|---|---|---|
| signal（hero A） | 女神立石柱顶，手举星火，天空同心涟漪扩散，人群仰望 | 被看见 / 搜索信号 |
| colossus（hero B） | 巨型金梨纪念碑，三人在贴金擦拭 | 打磨品牌（"Gilding the pear"） |
| reveal（hero C） | 男子拉开巨幅黑色半调帷幕 | "Pear makes you appear" |
| v28/v51/v61 桥接 | 柱变树 / 推近细节变成新场景 | 从"宣言"进入"工作" |
| renaissance | 嫁接→成树→金梨→采摘→切半→递出 | 建设→增长→脱颖而出→收益分成 |
| plan | 金梨建筑工地→揭示为纸面蓝图 | 策略与工程 |
| tree / flysky | 梨树、金梨飘升、星座连线 | 增长、外链建设 |
| coda / trans | 蓝图、园丁 | 执行、培育（接页脚循环） |

Hero 三段每次访问**随机选一段**（`?hero=signal|colossus|reveal` 可指定），每段带 `origin` 参数标记转场推近的聚焦点。

## 美学原则

1. **活画（living painting）**：hero 与页脚是无缝循环的 cinemagraph——构图不动，只有环境微动（衣摆、涟漪、火苗、人群轻晃）。克制即奢华。（pear.no 原站是 10 秒 / 60fps；**本流水线生成 4–6 秒、收敛后交付约 6.6 秒 / 24fps**，不要照抄原站数字。）
2. **limbo 空间**：纯白或纯蓝无缝背景，人物如文艺复兴油画/新古典主义雕像，无透视地面——让"印刷品插图"气质成立。
3. **印刷缺陷贯穿到影像内部**：云是半调网点的、水流是棋盘格"未渲染"纹理、金梨上有彩虹色差（misregistration）——错位套印不只是标题样式，是整个世界观。
4. **单一品牌图腾**：梨贯穿所有段落，反复变奏（金梨、梨树、梨形纪念碑、切开的梨）。
5. **运镜即转场**：push-in / pull-out / crane-up / tilt-down 承担全部"剪辑"功能；拉远揭示（pull-out reveal）是招牌手法。
6. **首尾帧焊接**：段落首尾帧严格匹配（构图、光线、主体位置），这是用 FLF2V 复刻此风格时最重要的纪律。
7. **一段文字，一帧属于它的画面（影像驱动叙事）**：pear.no 每个叙事节拍都有自己的画面——镜头推近/拉远让画面变成下一场景，下一句话才出现；**没有哪张图被拿来当两段文字的背景板**（本项目实测反例：首屏 F00 活画同时承担了 hero 标语、"三十秒档案"、"先理解人，再设计系统"三段文字）。所以写故事板时要同时出**"节拍 ↔ 帧"对照表**：每个节拍指向一个独有画面（共享帧只作焊接边界），并给每帧标好文字落位区（见 [asset-acquisition.md](asset-acquisition.md)「构图与留白」）。若某句话找不到属于它的画面，是分镜缺一帧，回头补画面，不是把文字挂到已有的一张图上。反面教材与验收标准见 [pear-design-language.md](pear-design-language.md)「少即是多」第 2 条与 SKILL.md §1a。

## 技术实现要点（供复刻）

- Hero/页脚循环：mp4，**生成 4–6 秒 → 收敛为约 6.6 秒 / 24fps**（pear.no 原站为 60fps / 10 秒，本流水线的生成器做不到，不要在分镜阶段按 10 秒排），首尾帧一致（无缝 loop），`muted playsinline`。收敛判据与做法见 [comfy-flf-video.md](comfy-flf-video.md)「焊接与循环收敛的数值依据」。
- 滚动驱动段：**不用视频，用帧序列**（WebP，`f_001.webp` 编号，1440/768 双档按视口宽度选择），滚动进度直接映射帧号——比视频 `currentTime` scrub 更精准、无解码卡顿。**帧数由各段实际导出决定**（pear.no 原站在 121–362 帧区间；本流水线实测单段约 158 帧），别把数字写进 HTML，要按实际文件数推导。加载按需、前向偏重预取相邻帧。
- 转场由 WebGL shader 层叠加：噪点、颗粒、dither、色差、光晕、接缝溶解（JS 参数可见 `noise/grain/dither/hash/char/glow/seam/zoom`）。
- 自定义平滑滚动（lerp 惯性滚轮劫持）驱动整条 5350 单位的时间轴；`prefers-reduced-motion` 与触屏设备降级。
- 帧序列按需加载（`want`/`near` 预取相邻帧），两套分辨率按 `max-width:820px` 切换。

## 用 FLF2V 复刻时的落地建议

1. 先画**转场链故事板**：确定每段的首帧/尾帧；段间焊接通过**相邻两段复用同一张边界帧文件**实现——图像模型无法稳定复现同一场景，不要分别生成两张"相似"的帧。
2. 每段一次 FLF2V 生成（首帧+尾帧+视频提示词），时长 4–6 秒；首帧与尾帧是不同场景，视频提示词必须清晰描述首帧到尾帧的**具体变化过程**（转化路径 + 摄像机运动 + 主体微动），用 h3-json-director skill 以 FL2VA 模式撰写（见 comfy-flf-video.md 第三步）。
3. 段落内部不要要求模型切镜——一段一镜，切镜靠首尾帧链和前端 shader/帧序列拼接完成。
4. Hero 循环段：首帧=尾帧（同一画面），提示词只写环境微动（"火焰轻晃、衣摆微动、镜头完全固定"），生成后循环播放。
5. 生成后校验：目检视频运动是否符合提示词描述的转化路径；确认相邻两段工作流引用同一张边界帧文件（焊接靠文件复用，不靠像素相似）。
6. 导出帧序列（`ffmpeg -i out.mp4 f_%03d.webp` 或 PIL 转换）用于滚动 scrub 段；循环段保留 mp4。

## 场景链与线索物（分镜阶段的资产规范）

pear.no 的每段影片是**不同场景**（石柱→梨树→工地→星空→蓝图），靠两条线保持连续，这两条都要在写提示词之前设计好：

1. **场景链**：每段一个独立场景 + 一个隐喻主体，段间逻辑递进（被看见→建设→收获→计划→连接）。注意：由于 Midjourney 无法稳定复现同一场景（见第 3 条），"同场景时间流逝"（同一房间的三种状态）这类策略在本流水线中不可用——每帧必须是不同主体或场景。
2. **线索物（motif）**：同一物体/颜色/形状在每段变奏重现（梨：金梨→梨树→纪念碑→切开的梨）。提示词层面：为线索物写一段固定描写句（形状、材质、颜色），逐帧复用。
3. **跨场景焊接策略**（脚本阶段逐段选定）：Midjourney 无法稳定复现同一场景的构图与机位，"同画面双状态"（同一构图只改叙事要素）**不可行，不要使用**。每张参考帧是不同的主体或场景，默认用**异场景转化**——首帧与尾帧是两个不同画面，由视频模型的运动完成过渡：
   - **推近变形**（pear.no 招牌，首选）：首帧推近一个细节（画框、门洞、切面），尾帧就是细节内部的世界——首帧的提示词**必须包含那个细节**，两帧提示词成对设计；
   - **运动转化**：镜头运动（升起、拉远、横移）或主体运动自然带出场景转换（工地拉远揭示为纸面蓝图）；两帧之间要有可读的转化路径，完全无关的两张图插值会崩坏；
4. **焊接帧纪律**：段间共享的边界帧**必须复用同一张图片文件**（A 段尾帧与 B 段首帧指向同一文件）——这是唯一可靠的焊接方式；绝不试图让图像模型分别生成两张"相似"的帧。分镜阶段标出所有共享帧，共享帧只生成一次。
