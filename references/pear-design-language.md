# pear.no 式设计语言规范

pear.no 的核心气质："一份活版印刷的招股书"（letterpress prospectus）——把印刷品的物质感搬进浏览器，再用滚动驱动让它动起来。以下规范是可复用的设计语言，不是对该站的复制。

## 配色与材质

> **配色不由 agent 单方面决定。** 下面这套是"纸张/墨色/单一强调色"的设计语言约束，**不是可以直接落地的最终色板**：具体色值、明度策略（亮字压暗区还是墨字压亮区）、冷暖倾向，必须先给用户 2–3 套方案让用户拍板，选定后才写进 `:root`。**对比物是风格校准产出的真实出图（Midjourney 原始画面），不是 agent 专门搭的 HTML/CSS mock 页面**——自己搭页面会引入版式/字体/留白这层额外变量，盖过配色本身。原因与验收要求见 SKILL.md §1b 与 §6。

- 基底：纸张色。米白/奶油（`#f4efe6` 附近）为主底，深棕/墨黑（`#1a1512`）为文字与深色段落底。
- 点缀：单一强调色（pear.no 用梨绿/金色系），只用于链接、CTA、装饰线。
- 纸感：全站叠加极淡的噪点/纸纹（SVG `feTurbulence` 滤镜或平铺 PNG，opacity 0.03–0.06）。
- 半调（halftone）：图像上叠加网点纹理，模拟印刷网版。用 CSS 背景 `radial-gradient` 网点 + `mix-blend-mode: multiply/overlay` 实现，不烘焙进图片。

## 字体与排版

- 标题：高对比衬线 display 字体（如 Playfair Display、Cormorant、EB Garamond；Google Fonts CDN）。字号戏剧化——hero 标题可达 `clamp(3rem, 12vw, 11rem)`。
- 正文/标注：几何或新怪诞无衬线（如 Inter、Space Grotesk），小字号、大 letter-spacing、全大写用于眉题（eyebrow label）。
- **错位套印（misregistered print）**：标题的标志性处理。同一文字渲染两层，偏移 2–6px，分别上色（如墨黑 + 强调色），用 `mix-blend-mode: multiply` 叠加，模拟印刷套准偏差。标题必须保持为真实文本（可索引、可选中），禁止截图代替。
- 竖排/旋转标注、页码式编号（"№ 01"）、花饰分隔符（❦ ❧ 或细线）强化印刷品气质。

## 布局

- 桌面优先。不对称编辑式网格：文字块与图像错位重叠，留白大胆。
- 段落之间用全宽深色段或全屏媒体段打断节奏（像书的扉页/插页）。
- 图像处理：油画/版画图片常加双色化（duotone）或降低饱和度，统一进纸色调；可加细边框 + 图注（figcaption，小号斜体），像画册插图。

## 全页影片舞台（关键架构，实测踩坑后确立）

**不要把影片做成页面中段的一个独立 section**——那样影片与前后内容必然割裂。pear.no 的实际架构是：

1. **影片是永远在场的固定舞台**：`position: fixed; inset: 0; z-index: 0` 的舞台层（内含循环 mp4 + 帧序列 canvas 两层），贯穿整页；所有内容 section（z-index 1，透明背景）在舞台上方滚动经过。
2. **全局时间轴，而不是段落级 scrub**：每个内容 section 用数据属性声明自己在影片中的角色——`data-seg="s1"`（本区滚动进度映射到 s1 段帧序列的 0..末帧；帧号**每段各自从 f_001 起**，不要写全站绝对帧号）或 `data-video="hero|footer"`（本区切回对应活画循环）或两者皆无（影片定格在上一段末帧）。一个 rAF 循环读视口中心位置，驱动帧号、活画/画布交叉淡化、调光层（`#dim`）不透明度和幕次指示牌。
3. **内容在舞台上方"表演"**：宣言逐行显现、纸面浮动板（半透纸底 + 硬阴影）随滚动登场并带轻微视差、引文浮在影片末帧之上——所有演出都以影片为布景，幕次指示牌（Act I / II…）钉在角落随区间切换。
4. **焊接点复用**：帧序列第 N 段末帧 = 循环视频首帧 = 第 N+1 段首帧——段间共享的边界帧来自同一张源图文件（图像模型无法稳定复现同一场景，焊接靠文件复用，不靠重新生成相似帧），因此"帧序列 → 活画视频 → 帧序列"的交叉淡化是无缝的。
5. **定格区要处理"直接跳入"**：无 `data-seg` 的区间沿用上一区间末帧——但要记住当前帧号可能是冷的（刷新恢复滚动位置、锚点跳转时影片从未播过），此时要吸附到上一区间的末帧再定格，否则会错误地显示第一帧。
6. 页脚用不透明纸底"合上书本"，结束影片。
7. **hero 首屏内容必须锚定第一个 100vh**（对舞台/首屏做绝对定位容器）：挂在超高 section 底部的 hero 内容，在任何滚动位置都不可见（实测踩坑）。

## 影片之上的文字（pear.no 的实际做法，经其 CSS 证实）

**不要用卡片/面板**。 pear.no 在影片上方呈现文字的方式：

- **文字直接排在画面上**：无底板、无边框、无阴影、无圆角。标题是细衬线大字（weight 300，约 5vw），正文是小号无衬线（13–19px，max-width ~27em，line-height 1.3–1.9）。
- **行遮罩显现（可选，见下面的位移预算）**：每行包在 `overflow:hidden` 行盒内从 `translateY(120%)` 升起——文字像从画面里长出来。登场节拍：序号 → 1px 细线 scaleX 展开 → 标题逐行升起 → 正文浮现，各文字块按本幕滚动进度错开（不是同屏齐出）。
  ⚠️ **这条与"零位移"要求冲突，必须先问用户要哪一种。** `translateY(120%)` 是"每行从自身高度 1.2 倍处升上来"（实测约 50px），在滚动容器里很容易被读成"文字从下面升上来"——正是巡游式动画的一种。用户明确说"不要大范围运动"时，**改用纯 opacity + blur 的逐项错开**，并去掉 `.ln{overflow:hidden}`（详见「分幕文字动画：巡游式退场的完整错误与修法」）。
- **1px 细线分隔**（scaleX 动画）代替边框；罗马数字/小徽章式序号（极小全大写、几乎不可见的半透明底 `#ffffff1a`）代替卡片标题栏。
- **落位在画面的视觉休息区**：文字排在墙面、天空、夜色等平静区域，避开主体。 pear.no 用 limbo 留白空间所以几乎不需要压暗；油画类复杂画面可在文字后方加一团**边缘完全羽化的径向柔光**（`radial-gradient` + 大负 inset），绝不能出现硬边矩形。
- 反面教材（本项目踩过）：纸底色块 + 黑框 + 硬偏移阴影的"便签卡"——它把活画切成前后两层，与印刷世界观无关。

## 少即是多：文字与影片构图的呼应（本轮最重要的设计教训）

**文字必须与背景影片的构图相呼应，不是填满页面。** 规范：

1. **版式与画面必须建立关系，禁止相互孤立**：每个文字块的落位都要与背景帧的构图元素形成可指认的关系——**对齐**（文字块边缘/基线与画面中的桌沿、书脊、画框、建筑线对齐，像印在画面上）；**对话**（文字块与画面主体分居左右/上下，形成对视张力，如左文右物）；**动线衔接**（CTA、序号落在画面视觉动线的端点或起点，如羽毛笔—签名—火漆的排列线）；**明暗反用**（亮字压暗区、墨字压亮区，随帧区间明度变化切换配色而非一套到底）。排版前先逐帧读画面：标出主体位置、明暗分区、视觉动线，再决定文字落位——不允许脱离画面内容凭空摆版式；
2. **影像驱动叙事：一段文字，一帧属于它的画面（一图一文）**（本轮最重要的教训）。**每一段叙事文字都必须由它自己的画面承担**——新的帧、新的运镜、新的构图；**禁止一张图当两段以上文字的背景板**：同一帧 ID、同一活画循环、同一 `data-frames` 区间只能承载一段文字。否则影像没有为每个节拍生产画面，是文字在替影像推进叙事。
   - **反面教材（本项目实测）**：首屏那张 **F00 活画被复用成三幕文字的背景**——① 幕 1 hero 标语（`data-video="hero"` ⇄ L01 活画 = F00）"让差异成光，让匹配成弦"；② 幕 2"三十秒档案"（`data-frames="0,0" data-hold="0,0"`，定格在 F00）；③ 幕 3 宣言（`data-frames="0,123" data-hold="0,14"`，V01 首帧仍是 F00）"先理解人 / 再设计系统"。**一段动画承载了三段文字叙事。**
   - **判定**：逐幕列出（幕序、文字块、背景帧 ID / `data-frames` 区间），**同一帧 ID 出现在两幕以上的文字背景上即违规**；代码层表现为 `data-hold` / `data-frames` 定格区间被相邻两幕文字共用或交叠。
   - **修法二选一**：给该节拍补一帧画面/一段运镜（可以是新生成的帧，也可以是本段内尚未被文字占用的区间），或删掉这段文字（通常它说的就是相邻幕的同一件事）；**不要**用调字号、压行数、换落位来掩盖。
   - **共享帧只作焊接边界**（前段末帧 = 后段首帧）：焊接帧上的文字只能属于焊接点所属的那一段。
   - 顺带：同一幕内文字本身也要克制——正文块行数从严（一两行说清楚就停），条目宁少勿滥。
3. **落位对照每帧的平静区**：分镜阶段的文字落位表（见 asset-acquisition.md「构图与留白」）要在 QA **逐帧验证**，不只查段首段尾——影片中段主体移动后，原来的平静区可能已被占；
4. **文字随帧区间让位**：同一幕内的文字块应随 scrub 时间轴淡入/淡出并换位置，保证画面主体（人物、关键道具）**全程不被文字遮挡**——而不是一个文字块钉死整幕；
5. **纸底编辑版面段用于节奏对比**（像书的插页），但条目同样宁少勿滥——它是呼吸口，不是第二个正文堆场。

## 动效

技术基线：GSAP + ScrollTrigger，可选 Lenis 或自实现 lerp 惯性滚动。CDN 起步最快，但**交付前应把 GSAP 本地化**（`SKILL.md` 要求"页面离线打开可用，CDN 除外需在交付说明中注明"；实测项目的做法是把 gsap 3.12.5 落到本地并去掉外链）。字体同理——Google Fonts 外链会带来 FOUT 与"换字后触发器位置过期"双重问题，自托管更稳。

- **活画循环（living painting）**：hero 与页脚用**无缝循环 mp4**——构图固定，只有环境微动（衣摆、涟漪、火苗）。克制即奢华。⚠️ 时长以产物为准：**生成 4–6 秒，收敛后交付约 6.6 秒 / 24fps**（pear.no 原站是 10 秒 / 60fps，本流水线复刻不了那个规格，不要照抄它的数字）。
- **滚动叙事段用帧序列，不用视频 scrub**：pear.no 实际做法是 WebP 帧序列，滚动进度直接映射帧号——比 `video.currentTime` 更精准、无解码卡顿。退而求其次才用 scrub 视频（需密集关键帧）。**具体规格（帧数区间、`f_001.webp` 编号、1440/768 双档与 ≤820px 切换）以 [film-language.md](film-language.md) 为准**，本文件不重复。双档的方向是**向下做低档**（768 宽给 ≤820px 视口，实测 s1 段 5.94MB → 2.22MB，降约 63%）；源分辨率不支持向上做高档；两档同用管线的 q94 与轻度 USM（不要把低档另降质量——锐度策略会被丢掉）。
- **运镜即转场**：段落间没有硬切。推近细节→细节变成下一场景；拉远→揭示"这是纸上的图"；首尾帧严格焊接。详见 [film-language.md](film-language.md)。
- **转场质感层**：滚动切换段落时叠加噪点/颗粒/色差/溶解（CSS filter、canvas 或 WebGL shader），模拟胶片与印刷缺陷。
- **逐行显现**：宣言段落的每行文字随滚动显现 + 透明度渐入（`opacity: 0` → 1，stagger）。**是否叠加位移取决于用户要求**：默认可做 ≤3em 的纵向微位移，但若用户强调"不要运动"，就只做 opacity + blur——见下一节。
- **文字进出场绝不"巡游"**：文字必须在其最终落位的**邻近范围**进出，**禁止**从视口最下方长距离上浮进入、或上浮到视口最上方才消失——那会暴露"元素在页面上旅行"的机械感，打破活画布景的幻觉。
  ⚠️ **这一条比它看起来难得多，且"小位移"仍然会被用户读成巡游。** 完整成因（sticky 壳无处可粘 / 行盒遮罩 / 退场晚于释放点 / 无退场轴 / 归零即显示 / 窗口退化成 1px）与可抄的实现、**以及能真正证明修好的验收方法**，全部记在下面「分幕文字动画：巡游式退场的完整错误与修法」一节——**做文字动画前先读那一节**。
- **进出场方式逐幕多样**：纯溶解（opacity + 轻微 blur）、逐项错开、细线展开、水平微滑等按幕轮换，避免全站只有一种。
- **视差**：图像以略慢于滚动的速度移动（`y` 百分比 ±10–20%），制造层次。
- **固定段**：服务陈列等段落要让长内容"钉住"时，**优先用 CSS `position: sticky`**（模板与实测项目都用它：`sticky` 容器 + 100vh 内部层），而不是 GSAP `pin:`。**只有确实需要 pin 时**才用它，且 pin 的 ScrollTrigger 必须在其他触发器**之前**创建——pin-spacer 会推挤后续文档流，否则后续触发器起点全部错位。
  ⚠️ **硬约束：承载 sticky 壳的 section 必须比壳高。** `section{height:100vh}` + `.inner{height:100vh}` 时 sticky **无处可粘**，壳会跟着文档流正常上移——挂在上面的文字于是以 1:1 速度滚过整个视口（实测 **720px**），这就是巡游式动画最强的成因，而且它不报错、不报警，只有量位移才看得见。给 section 至少多留一屏（如 `210vh`：100vh 贴住 + 110vh 用来原地淡出）。
- **动效门控**：`from` 类动画在窄屏静态流下容易留下"隐形文字"（opacity 停在 0）。实测项目的做法是**给需要动效的元素加 `.motion` 类显式开启**；用 `gsap.matchMedia` 全局门控也可以，但必须在每个断点分支里把终态显式写回。
- 克制原则：每屏 1–2 个动效主角，其余静态。动效服务于叙事节奏，不是炫技。

实测踩坑（GSAP/滚动集成的硬约束）：

- **网络字体换入会推高各幕高度**，触发器位置随即过期——必须 `document.fonts.ready.then(() => ScrollTrigger.refresh())`；
- **自实现 lerp 惯性滚动的兼容要点**：页面真实 `scrollY` 始终等于平滑值（rAF 里 `scrollTo`），推进后调 `ScrollTrigger.update()`；监听原生 `scroll` 事件，外部滚动（键盘翻页/滚动条拖动/锚点跳转）与平滑值偏差 >2px 时直接吸附同步，不与 lerp 打架；`?frame=` 类调试钩子直接瞬落到位，不走 lerp。

## 分幕文字动画：巡游式退场的完整错误与修法（血泪教训，必读）

> 来源：一个真实项目里，用户**连续五轮**指出同一件事——"文字在从页面下方向上运动进入、
> 再向页面上方运动退出"。前四轮的"修法"都没修对，因为每一轮都在**量错的东西**。
> 这一节把错误的全貌、以及一个能真正证明修好的验收方法记下来。

### 症状到底长什么样

用 `position: sticky` 做"全页影片舞台"时（`sticky` 壳 + 100vh 内部层），
文字挂在壳里绝对落位。**如果处理不当，一组文字块的可见期会以 1:1 的速度跟着文档流上移**
——读者看到的是"文字从视口下方升起来、再从上方飘走"，而不是"文字本来就在画面上，
只是显影了"。这就是**巡游式动画（parade-like）**。

### 七个独立成因（全部实测踩过，缺一条都还会残留）

| # | 成因 | 症状 | 修法 |
|---|---|---|---|
| 1 | **sticky 壳的父级与壳等高** | 幕高 == 壳高时 sticky **无处可粘**，整屏文字以 1:1 速度跟页上移（首选屏尤其明显，实测位移 **720px**） | 父级必须高于壳。首屏写成 `210vh`（100vh 贴住 + 110vh 原地淡出） |
| 2 | **行盒遮罩的 `translateY(120%)`** | 每行从自身高度 120% 处升上来（≈50px），正是"从下往上进来" | 若要零位移，就别用行遮罩；见下面"位移预算" |
| 3 | **段落/条目的 `y: 8–12`** | 小但可辨的上浮 | 收到 ≤6px，或改为纯 opacity + blur |
| 4 | **退场排在 sticky 释放点之后** | 释放后壳跟着文档流走，还在动的文字被读成"黏在幕布上被带走" | 退场必须**早于释放点**完成；释放点 = `幕top + 幕高 − 视口高` |
| 5 | **单帧停驻的幕根本没建退场轴** | 文字全程 opacity 1，跟着释放后的壳**整屏滚出视口**（实测从 y=343 漂到 −520） | 退场轴**无条件建**；没有帧区间可排时，由**释放点倒推**一段 ramp |
| 6 | **进场轴的 t=0 写着"可见"** | 驱动逻辑把非当前幕归零（`time(0)`）时，**"归零"等于"显示"**——已淡出的幕在离开时又亮起来（实测 opacity 突回 1.00） | 让两条轴各自的 t=0 都代表**不可见**：可见度拆成两个变量相乘 |
| 7 | **进场窗口由帧号反推时退化成 1px** | `data-hold` 落在段首帧时，`yAtFrame(h0−5)` 就是**幕顶**，进/出场起止点只差 1px → 文字**硬切**出现（用户随即反馈"进出场动画要有"） | 文字窗口与帧号**解耦**：按幕的滚动长度给（进场 16% / 满显中段 / 退场 12%） |

### 关键实现：可见度拆成两个变量相乘

进场与退场是**两条独立时间轴**，播放头会停在不同位置。共用一个变量必然互相写坏。
正确写法是各管一个、相乘：

```css
.copy{ --vis:1; --ev:1; opacity:calc(var(--vis) * var(--ev)); }
```

```js
// 进场轴：--vis 0 → 1
tlIn.fromTo(blk, { "--vis": 0 }, { "--vis": 1, duration: .4, ease: "none" }, 0);
// 退场轴：--ev 1 → 0
tlOut.fromTo(blk, { "--ev": 1 }, { "--ev": 0, duration: 1, ease: "none" }, 0);
// 非当前幕归零：**只写 --vis，不要碰 --ev**
gsap.set(blk, { "--vis": 0 });
```

- 两条轴各自的 t=0 于是都代表"不可见"，播放头停在哪都不会写坏对方；
- ⚠️ 归零时多写一个 `--ev: 0` 会在行内留下脏值：回到该幕时退场轴虽停在 `--ev:1`，
  但补间没被重新渲染，行内一直是 0 → **文字永远不出现**。

### 位移预算（给"零运动"要求的项目）

用户说"不要有大范围运动"时，**不要把它理解成"小一点就行"**——那是四轮返工的根源。
可行的一套是：

| 元素 | 允许 | 不允许 |
|---|---|---|
| 标题行、玻璃字 | opacity + blur | 任何 transform |
| 正文块、条目 | opacity + blur + **≤6px** 纵向微生长 | 行遮罩、>6px 位移 |
| 整块 | opacity | 任何位移 |
| 细线 `.rule` | `scaleX(0→1)`（1px 的线，是它"存在"的方式，不是文字位移） | — |

"显影感"由三件事承担，全部不靠位移：**逐项错开**（序号→细线→标题逐行→正文→条目）、
**失焦复原**（`blur(6px)→0`）、**逐行分离**（标题必须按每行元素动，选 `h2` 整体只会整块一起出现）。

⚠️ 样式表里再加一道自检，把"标题行不许有位移"钉死：

```css
.copy h2 .ln, .copy h2 .ln>i, .copy .display .glass{ transform:none; }
```

（反面：把 `.rule` 也写进这条名单，它的 `scaleX(0)` 会被推翻，线变成 0×0 永远不出现。）

### 验收：必须量"用户感知到的那个量"

**这是本项目最贵的教训。** 前四轮的审计都不是"代码写错"，而是**量错了东西**：

| 审计当时量的 | 为什么看不见问题 |
|---|---|
| 整块 `.copy` 的视口坐标 | 行盒遮罩让**块内每一行**在动，块本身不动（实测块 0.00px、行在动） |
| 带 `data-frames` 的幕 | **首屏（hero）没有 `data-frames`，从来没被量过**（它的位移最大：720px） |
| `?smooth=0` 精确瞬落 | 用户用的是 **lerp 惯性滚动**——滚轮停手后页面还在滑行，文字位移发生在**这段滑行里**；`?smooth=0` 下该量**恒为 0** |
| `require z.frames` | 只挂 `data-scroll-frames` 的活画幕（页脚 CTA）被**结构性静默跳过**，从未被任何一条检查覆盖 |

正确做法（**已固化成脚本，直接跑**）：

- [scripts/measure_text_motion.py](../scripts/measure_text_motion.py) —— 量位移。真实交互模式下给一次
  真滚轮推进，按帧记录视口坐标直到停稳。**可见期间位移 ≤2px**。已内置下面 1–4 条纪律。
- [scripts/audit_reveal_feel.py](../scripts/audit_reveal_feel.py) —— 量"动画还在不在"（下面第 5 条）。

背后的五条纪律：

1. **在真实交互模式下量**：给一次真实的滚轮推进（走 `lerp.by()` 那条路），
   然后按帧记录文字块的视口坐标直到停稳。判据：**可见期间位移 ≤ 2px**。
2. **覆盖率要穷举**：块 **与块内每一行**分别量；首屏单独量；
   帧轴取值统一走 `frames || scrollFrames`，不要让任何一幕只因为少写一个属性就溜掉。
3. **推进量要小于该幕的可见窗口**——否则一步跨过整段文字，
   采到的全是不可见状态（可见样本 0、位移恒 0），**等于没量**。
   短幕（如 1.3 屏）可粘余量只有 0.3 屏，用大推进必然跨过去。
   ⚠️ 采到 0 个可见样本时报出的 `0.00px` 是**假清白**，比测出问题更危险——
   脚本会自动收紧推进量重试，并把"没测到"判为失败。
4. **采样要非均匀**：进出场各只占幕长 12–16%，均匀取点会正好跨过它们。
   进出场区段密采，中段稀采。
5. 另外量一条"**动画还在不在**"：可见度必须**经过中间值**（不是 0→1 一跳），
   且同一时刻各元素的可见度要**拉开差距**（逐项错开）。
   修"零位移"时很容易把动画一起修没，这条防的就是它。

> **一句话**：判据必须落在**用户真正感知到的量**上。他动的是滚轮、页面在滑行，
> 那就必须在滑行过程中量；他看到的是行不是块，那就必须量行；
> 他的第一眼是首屏，那首屏就不能不在覆盖范围里。
>
> 补充一条同形的教训：**"不在某条筛选条件里"也是静默失败的来源。** 本项目里
> 有一幕因为只写了 `data-scroll-frames` 而没写 `data-frames`，于是它被
> `require frames` 的页面逻辑与三个审计脚本**同时**跳过——从未被任何检查覆盖过。
> 写审计时要把"取帧轴"这类取值收敛到一个函数（`frames || scrollFrames`），
> 页面与脚本两侧共用；**判据里每多一个硬条件，就多一类元素会无声地消失。**

## 降级与可访问性

- `prefers-reduced-motion: reduce`：禁用 scrub 与视差，**隐藏影片舞台（`#stage`）并切换为静态版式**——把影片降级成插画/静帧排在文档流里；不要指望"让视频停在 poster 上"（实测两版实现都是隐藏舞台，poster 可选）。逐行显现改为直接可见。
- 移动端：scrub 视频可选降级为自动播放循环或直接 poster 图；错位套印偏移量缩小。
- 所有图像有 `alt`；标题层级语义化；对比度满足 WCAG AA。

## CDP 截图验收坑位（QA 驱动，实测）

本类页面全靠 rAF 驱动（帧序列渲染、lerp 滚动、逐行显现），无头/后台 Chrome 的节流直接决定验收是否有效：

- **无头 Chrome 被遮挡（最小化/被其他窗口盖住/锁屏）时 rAF 完全冻结**——CDP 验收启动参数必须带 `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding`（及配套的 `--disable-background-timer-throttling`），否则滚动了但画面不动，截图全是过期状态；
- **连续跑多轮 QA 要清理残留 Chrome 实例**——同一 `--user-data-dir` / 调试端口会连到旧实例的旧标签页，验收的是缓存里的上一版页面；每轮开跑前杀掉残留进程或用全新 profile/端口。
